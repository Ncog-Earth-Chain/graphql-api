## Acceptance clauses

These are the bounded repair clauses supplied by the coordinator, not a fresh transcription of the Jira description:

1. All three roots refuse protected/tombstoned/undecidable transaction traces.
2. Block examine every tx and unavailable policy failclose.
3. Public DDB/nonDDB successful traces unchanged.
4. Bind block-number lookup to immutable hash to avoid lookup/trace reorg gap.
5. Cancellation propagation.
6. Preserve no offchain sidecar/key leak claim.

The three raw roots are `traceTransaction`, `traceBlockByNumber` and `traceBlockByHash`. They reach the corresponding repository methods, where the guard runs before the unchanged RPC bridge. A refused block trace returns an explicit error and no trace result, rather than a partial result presented as complete. The existing node verdict remains authoritative: GraphQL does not derive reader roles, tombstone state or an applied frontier itself. `internalTransactions` and `tracingAvailable` use the separate internal trace source; protected calldata still passes through `redactInternalInputs`. The current tests verify that source remains available and separately verify preservation of internal metadata and input redaction. Full resolver extraction/HTTP wiring remains later integration coverage.

## Residual risks

- GraphQL relies on its configured node's truthful transaction/block lookup and current calldata verdict. This repair does not authenticate a malicious upstream or prove that every node deployment implements identical policy. A policy change occurring inside one accepted request follows the node's existing request semantics; no cross-RPC atomic policy snapshot is introduced.
- Refusing a block when one transaction is protected intentionally withholds the entire raw block trace. Existing filtered internal-transaction views remain available through their separate path; this does not authorize a new raw output route. New partial raw-trace redaction, placement-aware routing, DDB history recovery, batch/receipt decoding and status/read-token additions remain outside this change.
- PLACE03 commitment-only calldata contains public routing/commitment metadata and keyed tags. Off-chain sidecars and digest keys are not supplied by these trace routes. Protecting historical plaintext calldata does not prove sidecar transport confidentiality, key custody or tenant erasure elsewhere.
- This is an API output-policy repair: no consensus word, feature flag, governance setter, signing domain, database migration or node RPC method is introduced. Consensus flag-off/older-validator compatibility, serial/parallel execution, anchor rebuild and governance bounds are therefore not new activation obligations for this change. Public trace compatibility and legacy calldata policy are covered above; full system rollout remains separate.
- The guard adds lookup/verdict work to trace requests. Existing tracing timeouts, API budgets, RPC batching and cancellation remain necessary; component tests do not establish production capacity, crash behavior of the upstream node or protection against every resource-exhaustion workload.
